# 카카오 닉네임 로그인 설계

## 목표

Vue의 Kakao JavaScript SDK로 닉네임만 동의받아 카카오 로그인을 제공한다. 카카오 이메일은 요청하거나 로컬 계정 연결에 사용하지 않으며, Kakao 고유 사용자 ID로 기존 로컬 계정과 분리된 계정을 식별한다.

## 현재 상태

- `frontend/src/LoginPage.vue`에는 이메일/비밀번호 로그인 및 회원가입이 있다.
- `app.models.User`는 이메일과 해시된 비밀번호가 필수다. 따라서 소셜 사용자 정보를 이 테이블에 억지로 넣지 않는다.
- 앱의 JWT는 `sub`에 로컬 사용자 ID를 담는다.
- 카카오 개발자 콘솔 앱 `mlops` (ID `1614689`)은 카카오 로그인과 동의 항목이 아직 설정되지 않았다.

## 아키텍처

1. 프론트엔드는 Kakao JavaScript SDK v2를 로드하고 `Kakao.Auth.authorize()`로 `profile_nickname`만 요청한다. 로그인 시작 때 만든 무작위 `state`를 브라우저 임시 저장소에 보관하고, 사용자는 카카오 동의 후 `/login/kakao/callback`으로 돌아온다. 프론트엔드는 돌아온 `state`를 검증한 뒤 쿼리의 인가 코드를 `POST /user/kakao/login`으로 전달하고 URL에서 인가 코드와 state를 제거한다.
2. 백엔드는 인가 코드를 카카오 토큰 API에서 액세스 토큰으로 교환하고, 그 토큰으로 카카오 사용자 정보 API를 호출한다. 응답에서 고유 사용자 ID와 닉네임만 사용하며 이메일 필드는 읽거나 저장하지 않는다. 클라이언트가 보낸 닉네임은 신뢰하지 않는다.
3. 백엔드는 별도 `KakaoAccount` 테이블에 카카오 ID와 닉네임을 upsert하고, 앱 JWT를 발급한다. JWT subject는 `kakao:<id>` 형식으로 로컬 정수 ID와 구분한다. 기존 로컬 로그인과 토큰 subject 형식은 유지한다.
4. 현재 DB 초기화의 `create_all`이 새 테이블을 생성하므로 기존 `users` 테이블 변경이나 기존 데이터 마이그레이션은 필요하지 않다.

## 사용자 동작 및 오류

- 로그인 화면에 카카오 로그인 버튼을 추가한다. 로컬 로그인/회원가입 UI와 동작은 유지한다.
- 성공하면 기존 로그인과 동일하게 `access_token`을 저장하고 성공 상태를 알린다.
- 사용자가 동의를 취소하면 콜백의 오류 파라미터를 처리해 취소 안내를 보이고 로컬 로그인 화면은 유지한다. state가 없거나 맞지 않으면 코드를 서버에 보내지 않고 로그인을 거부한다.
- 카카오 토큰이 거절되면 401, 카카오 서비스에 연결할 수 없으면 502를 반환한다. 기존 API 응답 envelope `{code, message, result}`를 사용한다.
- 같은 카카오 ID가 재로그인하면 저장된 계정을 갱신하고 같은 계정으로 로그인한다. 다른 카카오 ID가 같은 닉네임을 쓰는 것은 충돌이 아니다.
- 이메일을 받아오지 않으므로 로컬 이메일과의 중복 검사는 하지 않는다. 로컬 계정과 카카오 계정은 자동 연결되지 않는다.

## 카카오 개발자 설정

- 콘솔 앱에서 카카오 로그인을 활성화하고 콜백 URI `http://localhost:5173/login/kakao/callback`을 등록한다.
- 동의 항목에는 닉네임(`profile_nickname`)만 설정하고 이메일 동의 항목은 요청하지 않는다.
- 웹 플랫폼 개발 도메인으로 `http://localhost:5173`을 등록한다.
- JavaScript 키는 `VITE_KAKAO_JAVASCRIPT_KEY` 환경 변수로 프론트엔드에 제공하며 소스 코드에 고정하지 않는다. 백엔드에는 `KAKAO_REST_API_KEY`와 콜백 URI를 환경 변수로 제공한다. 카카오 토큰 API의 클라이언트 시크릿 기능이 앱에서 활성화된 경우에만 시크릿을 백엔드 환경 변수로 제공하고 프론트엔드에는 노출하지 않는다.

## 범위 밖

- 기존 로컬 계정과 카카오 계정의 연결/병합
- 이메일 수집 또는 이메일 기반 중복 검사
- 운영/배포 도메인 등록 (배포 도메인이 주어지지 않음)
- 카카오 연결 해제 웹훅과 앱 내 계정 삭제

## 검증 기준

- 백엔드 pytest: 정상 토큰 로그인, 같은 카카오 ID 재로그인, 잘못된 토큰, 카카오 API 연결 실패, JWT subject 구분, 이메일을 사용하지 않음을 검증한다. 카카오 네트워크 호출은 테스트에서 대체한다.
- 프론트엔드 Jest: SDK 초기화와 닉네임 범위 로그인, 액세스 토큰 API 전달, 성공/취소/실패 메시지 동작을 검증한다.
- `npm test`, `npm run build`, `pytest`가 통과한다.
- Chrome DevTools로 로컬 화면을 확인하고 실제 카카오 동의 화면이 이메일 권한 없이 닉네임만 요청하는지 확인한다.

## 공식 SDK 동작 근거

최신 Kakao JavaScript SDK 문서의 웹 로그인 흐름은 `Kakao.Auth.authorize()`로 인가 코드를 리다이렉트 URI에 전달한 뒤 서버에서 토큰을 교환하는 방식이다. 백엔드 사용자 정보 조회는 `https://kapi.kakao.com/v2/user/me`에 Bearer 토큰을 전달한다.
