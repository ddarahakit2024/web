# 01. 기능 로드맵 — "판매되는 사이트"에서 "수강되는 서비스"로

## 1. 현재 상태 진단 (2026-10-20 기준 코드)

### 구현되어 있는 것

| 영역 | 내용 | 위치 |
| --- | --- | --- |
| 이메일 회원 | 가입(PBKDF2 해시), 로그인 → JWT를 HttpOnly 쿠키로 발급(30분), `/user/me` | `app/api/routers/users.py`, `auth.py`, `app/core/session.py` |
| 카카오 로그인 | 인가 코드 → 프로필 조회 → `kakao_accounts` 저장 | `app/api/routers/kakao_auth.py` |
| 강의 조회 | 공개 목록/상세, 커리큘럼은 JSON 컬럼 | `app/api/routers/courses.py`, `app/models/course.py` |
| 결제 | PortOne V2 주문 생성, 결제 확인(서버에서 금액·상태 재검증), 중복 구매 409 | `app/api/routers/payments.py` |
| 화면 | 카탈로그, 상세, 로그인, 결제 완료 | `frontend/src/views/` |
| 테스트 | pytest 30개, Jest 47개 통과 | `tests/`, `frontend/src/**/*.test.mjs` |

### 핵심 공백 — 지금은 "돈은 받는데 볼 게 없는" 상태

1. **강의 콘텐츠와 시청 경로가 없다.** 커리큘럼이 레슨 제목 문자열 목록뿐이고, 영상·재생·진도 개념이 없다.
2. **수강권(Enrollment) 개념이 없다.** `PAID` 주문이 존재하는지가 사실상 권한인데, 이를 조회·회수(환불)하는 API가 없다.
3. **관리자(본인) 기능이 없다.** 강의 등록/수정/공개 여부를 DB를 직접 고쳐서 해야 한다.
4. **결제가 브라우저 콜백에만 의존한다.** 결제 후 사용자가 창을 닫으면 `confirm`이 호출되지 않아 "돈은 빠졌는데 수강 불가"가 생긴다(웹훅 없음). 환불/취소, 주문 만료, 동시 confirm 경합 처리도 없다.
5. **계정이 이원화되어 있다.** `users`(이메일)와 `kakao_accounts`가 따로 있고 결제는 `buyer_subject` 문자열(`"1"`, `"kakao:123"`)로 연결된다. 계정 연결·탈퇴·관리자 권한 부여가 어렵다. 로그아웃, 비밀번호 재설정, 회원 탈퇴도 없다.
6. **운영 기반이 없다.** 스키마 변경이 `create_all`뿐이라 컬럼 추가 시 기존 `app.db`가 깨진다(마이그레이션 없음). JWT 기본 키 허용, CORS 하드코딩, 로깅·에러 추적·백업·배포 구성이 없다.
7. **법적 필수 요소가 없다.** 이용약관, 개인정보처리방침, 환불 규정, 사업자 정보 표시, 약관 동의 기록.
8. **프런트 구조 한계.** 라우터 라이브러리 없이 `window.location.pathname` 분기(`App.vue`)라 페이지가 늘면 유지가 어렵다. 이전 프로젝트 잔재(`PostList.vue`, `postFilters.js`, `public/stays/*.jpeg`, `frontend/kakao-dev-test.db`)가 남아 있다.

## 2. 우선순위 원칙

- **P0 (출시 차단)**: 없으면 실제로 돈을 받고 서비스할 수 없거나, 법적·금전적 사고가 나는 것.
- **P1 (출시 직후)**: 매출과 신뢰를 올리는 것. 없어도 운영은 가능.
- **P2 (확장)**: 수강생과 매출이 쌓인 뒤 검토.

단일 강사 사이트이므로 **멀티 강사, 강사 정산, 마켓플레이스 기능은 만들지 않는다.** 관리자는 본인 1명이며 `role=admin` 계정 하나로 충분하다.

## 3. P0 — 출시 전 필수

각 항목의 "완료 기준"은 Codex 작업 카드의 `검증` 절에 그대로 옮겨 쓸 수 있게 작성했다.

### P0-1. 기반 정리 (다른 모든 작업의 전제)

- **DB 마이그레이션 도입(Alembic)**: SQLite `app.db` 유지. 현재 스키마를 최초 리비전으로 만들고, 이후 모든 모델 변경은 리비전으로만 한다. SQLite는 `ALTER` 제약이 있으므로 `render_as_batch=True` 사용.
- **SQLite 운영 설정**: WAL 모드, `foreign_keys=ON`, busy timeout. 단일 서버·소규모 서비스에서는 SQLite로 충분하다. (동시 쓰기가 많아지면 PostgreSQL 전환을 그때 검토)
- **설정 검증**: `APP_ENV=production`에서 `JWT_SECRET_KEY`가 기본값/짧은 값이면 기동 실패. CORS 허용 Origin, 쿠키 도메인/SameSite를 환경변수로.
- **Python 버전 고정**: `partitioned` 쿠키가 Python 3.14 이상을 요구하므로 버전을 명시하거나, 운영에서 프런트/API를 같은 사이트(예: `example.com` / `api.example.com`)로 두고 `SameSite=Lax` + `Partitioned` 제거.
- **프런트 기반**: `vue-router` 도입, 공통 axios 인스턴스(`withCredentials`, 기본 주소 `http://127.0.0.1:8000`, 401 처리), 로그인 상태 스토어. 잔재 파일 제거.
- 완료 기준: 빈 DB에서 `alembic upgrade head`로 현재 스키마 생성, 기존 테스트 전부 통과, 운영 모드에서 기본 JWT 키로 기동 시 실패하는 테스트.

### P0-2. 계정 통합과 필수 계정 기능

- **모델**: `users`(id, email nullable, name, role, status, created_at) + `auth_identities`(user_id, provider=`local|kakao`, provider_user_id, password_hash). 카카오 로그인도 `users` 행을 갖게 하고, JWT `sub`는 항상 `users.id`.
- 기존 `kakao_accounts`, `payment_orders.buyer_subject` 데이터를 마이그레이션으로 이전.
- **로그아웃**: `POST /user/logout`이 같은 속성으로 만료 쿠키 응답.
- **세션 유지**: 30분 만료 후 강의 시청 중 튕기지 않도록 리프레시 토큰(HttpOnly, 회전) 또는 슬라이딩 만료.
- **비밀번호 재설정**: 이메일로 1회용 토큰(만료 30분). 이메일 발송 서비스 필요(결정 항목).
- **회원 탈퇴**: 개인정보는 삭제/익명화하되 결제·환불 기록은 법정 보존 기간(전자상거래법상 대금결제·청약철회 기록 5년) 동안 유지.
- **약관 동의 기록**: 가입 시 필수 약관 버전과 동의 시각 저장, 마케팅 수신 동의는 선택·별도.
- 완료 기준: 이메일/카카오 사용자 모두 `users.id` 기준으로 구매·수강 가능, 로그아웃 후 `/user/me` 401, 탈퇴 사용자의 주문 기록은 남고 이메일·이름은 익명화.

### P0-3. 관리자(본인) 강의 관리

- `users.role = 'admin'` 하나. 모든 `/admin/*` API는 관리자 의존성으로 보호하고, **비관리자 403 테스트를 반드시 포함**.
- 강의 CRUD: 제목, slug, 요약, 상세 설명(마크다운), 가격, 정가/할인가, 썸네일, 카테고리, 상태(`draft` / `published` / `hidden`), 노출 순서.
- 공개 API(`GET /courses`)는 `published`만 노출.
- 썸네일 업로드: 로컬 저장보다 오브젝트 스토리지(S3 호환, Cloudflare R2 등) 권장. 최소한 파일 형식·크기 검증.
- 관리자 화면 `/admin`: 강의 목록, 편집 폼, 커리큘럼 편집(P0-4), 주문/수강생 조회(P0-6, P0-8).
- 완료 기준: 관리자만 강의 생성·수정·공개 전환 가능, `draft` 강의는 공개 목록/상세에서 404.

### P0-4. 커리큘럼 정규화 — 섹션과 레슨

- `course_sections`(course_id, title, position) / `lessons`(section_id, title, type=`video|text|file`, duration_sec, is_preview, position, video_asset_id, body).
- 기존 `courses.curriculum` JSON을 마이그레이션으로 이전 후 컬럼 제거.
- 상세 API는 레슨 제목·길이·미리보기 여부만 공개하고 **영상 ID나 재생 URL은 절대 포함하지 않음**.
- 관리자 API로 섹션/레슨 생성·수정·삭제·순서 변경.

### P0-5. 영상 호스팅과 보호 재생

- **영상 파일을 FastAPI가 직접 서빙하지 않는다.** 대역폭·트랜스코딩·다운로드 방지를 직접 해결하기 어렵다.
- 외부 VOD 서비스 사용(결정 항목): Cloudflare Stream, Mux, AWS(S3+MediaConvert+CloudFront signed URL), 국내 Kollus 등. 최소 요건: HLS 적응형 스트리밍, 서명된 단기 재생 토큰, 도메인 제한. 불법 복제가 걱정되면 DRM 지원 업체.
- `GET /lessons/{id}/playback`: 수강권 확인(또는 `is_preview`) 후 짧은 만료(예: 수 분~수 시간)의 재생 토큰/URL 반환.
- 관리자 업로드: 백엔드가 VOD 업체의 직접 업로드 URL을 발급 → 브라우저가 업체로 직접 업로드 → 업체 웹훅/폴링으로 처리 완료 상태 반영.
- 테스트: VOD 업체 클라이언트는 인터페이스로 분리하고 테스트에서는 가짜 구현 사용. 미수강자 403, 미리보기 레슨 공개, 만료 토큰 형식을 검증.

### P0-6. 수강권(Enrollment)

- `enrollments`(user_id, course_id, source=`payment|admin|free`, order_id nullable, status=`active|revoked`, granted_at, expires_at nullable). `(user_id, course_id)` 활성 수강권 유일.
- **결제 확정과 같은 트랜잭션에서 생성**. 결제 확정 로직은 confirm API와 웹훅(P0-7)이 공유하는 하나의 서비스 함수로.
- 관리자 수동 부여/회수(지인, 보상, CS 대응).
- API: `GET /me/courses`(내 강의실), `GET /courses/{id}`에 로그인 사용자의 `enrolled` 여부 포함.
- 수강 기간(평생 / N개월)은 결정 항목. `expires_at`으로 둘 다 지원 가능.

### P0-7. 결제 신뢰성

- **PortOne 웹훅 수신** `POST /payments/webhook`: 서명 검증, 같은 이벤트 중복 수신에 멱등, 웹훅 내용은 신뢰하지 않고 PortOne 결제 조회 API로 재확인 후 반영.
- **주문 상태 머신**: `READY → PAID → CANCELLED/REFUNDED`, `READY → FAILED/EXPIRED`. 허용되지 않은 전이는 거부.
- 동시성: confirm과 웹훅이 동시에 와도 수강권이 한 번만 생성(유니크 제약 + 트랜잭션).
- 오래된 `READY` 주문 만료 처리, 무료(0원) 강의는 결제 없이 수강권 발급.
- 결제 대사(reconciliation): 관리자 화면 또는 스크립트로 "PortOne에는 PAID인데 우리 DB는 READY" 목록 확인.
- 영수증/현금영수증은 PortOne·PG 설정으로 처리(결정 항목).

### P0-8. 환불·취소

- 환불 규정(결정 항목) 예시: 결제 후 7일 이내이고 수강 진도가 일정 비율 미만이면 전액 환불.
- 디지털 콘텐츠는 청약철회 제한 사유가 있지만, **사전 고지와 미리보기(시험 사용) 제공이 전제**다. 환불 규정은 상세 페이지·결제 직전·약관에 표시.
- 흐름: 사용자 환불 요청 → 관리자 승인 → PortOne 취소 API 호출 → 주문 `REFUNDED`, 수강권 `revoked`. 부분 환불은 P1.
- 완료 기준: 환불 후 재생 API 403, 같은 환불 요청 중복 처리 시 PortOne 취소가 두 번 호출되지 않음.

### P0-9. 학습 화면과 진도

- 내 강의실 `/my/courses`: 수강 중 강의, 진도율, 이어보기 버튼.
- 플레이어 `/learn/{courseSlug}/{lessonId}`: 영상, 커리큘럼 사이드바, 이전/다음 레슨, 완료 표시.
- `lesson_progress`(user_id, lesson_id, position_sec, completed_at, updated_at). 재생 위치는 일정 간격·이탈 시 저장(요청 폭주 방지).
- 진도율은 서버에서 계산(환불 규정 판단 근거가 되므로).

### P0-10. 법적·신뢰 페이지 (한국 기준, 최종 문구는 전문가 검토 권장)

- 통신판매업 신고, 사이트 하단 사업자 정보(상호, 대표자, 사업자등록번호, 통신판매업 신고번호, 주소, 연락처, 개인정보 보호책임자).
- 이용약관, 개인정보처리방침, 환불 규정 페이지와 버전 관리.
- 수집 항목 최소화(현재 이메일·이름·카카오 닉네임), 마케팅 수신 동의 분리.
- 결제 전 상품 정보·가격·수강 기간·환불 규정 고지.

### P0-11. 보안 기본

- 로그인·회원가입·비밀번호 재설정 요청 속도 제한(IP/이메일 기준).
- 쿠키 인증이므로 CSRF 대책: 상태 변경 요청에 `Origin` 검증 또는 CSRF 토큰. 현재 `SameSite=None`이라 특히 필요.
- 관리자 API 권한 테스트, 사용자 A가 B의 주문·진도·재생 URL에 접근 불가 테스트(IDOR).
- 보안 헤더, 오류 응답에 내부 정보 미노출(현재 500 핸들러가 예외를 삼키므로 **서버 로그에는 남기도록**).
- 의존성 취약점 점검(`pip-audit`, `npm audit`)을 검증 게이트에 포함.

### P0-12. 운영·배포

- 도메인, HTTPS, 단일 서버 구성(예: Caddy/Nginx → uvicorn, 정적 프런트 빌드 서빙) 또는 PaaS.
- `.env.production` 템플릿, 비밀값은 서버 환경변수로만.
- SQLite 백업: 주기적 스냅샷 + 외부 저장(예: Litestream으로 오브젝트 스토리지 복제), **복구 리허설 1회**.
- 구조화 로그(요청 ID, 사용자 ID, 결제 ID), 에러 추적(Sentry 등), `/health` 엔드포인트, 업타임 모니터링.
- 배포 런북(`docs/runbooks/deploy.md`), 결제 장애 런북(웹훅 실패·대사 불일치 시 조치).

## 4. P1 — 출시 직후 (매출·신뢰)

| 기능 | 요점 |
| --- | --- |
| 쿠폰·할인 | 정액/정률, 사용 기간, 1인 1회, 서버에서 최종 금액 계산 후 주문 금액 고정 |
| 상세 페이지 강화 | 미리보기 레슨, 강사 소개, FAQ, 총 강의 시간·레슨 수, 수강평 |
| 수강평 | 수강권 보유자만 작성, 관리자 숨김 |
| SEO·공유 | SPA라 메타 태그가 약함 → 강의 상세 프리렌더 또는 서버에서 OG 메타 주입, `sitemap.xml`, `robots.txt` |
| 분석 | 방문 → 상세 → 결제 시작 → 결제 완료 퍼널, 유입 경로(UTM) |
| 이메일 알림 | 가입 환영, 결제 완료 영수증, 환불 완료 |
| 관리자 대시보드 | 일/월 매출, 강의별 판매, 수강생 목록·검색, 주문 상세, 환불 요청 큐 |
| Q&A / 공지 | 강의별 질문 게시판(수강생만), 관리자 답변 알림 |
| 수료증 | 진도 100% 시 PDF 발급 |
| 부분 환불 | 진도 비례 등 정책에 따라 |

## 5. P2 — 확장

- 강의 묶음(번들) 상품, 구독/멤버십, 기간 연장 상품
- 강의 자료 다운로드(서명 URL), 퀴즈·과제
- 추가 소셜 로그인(구글, 애플), 계정 연결
- 마케팅 이메일(수신 동의자만), 장바구니
- PWA·모바일 최적화, 배속·자막
- PostgreSQL 전환(동시 쓰기·다중 서버가 필요해질 때)

## 6. 목표 데이터 모델 (초안)

```text
users ─┬─< auth_identities          (local / kakao)
       ├─< terms_agreements         (약관 버전별 동의)
       ├─< orders ──── payments     (PortOne 결제 1:N 시도 이력)
       │      └── refunds
       ├─< enrollments >── courses
       └─< lesson_progress >── lessons

courses ─< course_sections ─< lessons ── video_assets (VOD 업체 자산 ID, 상태)
coupons ─< coupon_redemptions
webhook_events                      (수신 원문, 처리 결과, 멱등 키)
admin_audit_logs                    (관리자 작업 기록: 가격 변경, 수강권 수동 부여, 환불)
```
