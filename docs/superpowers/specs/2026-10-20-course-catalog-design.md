# 강의 카탈로그 설계

## 목표

단일 강사가 판매할 온라인 강의를 수강생이 둘러보고, 강의의 가격과 구성을 확인할 수 있도록 공개 강의 목록과 상세 조회를 제공한다.

## 범위

- 강의 목록과 강의 상세 조회를 프런트엔드와 백엔드에 구현한다.
- 강의 정보는 SQLAlchemy 모델로 SQLite `app.db`에 저장한다.
- 이번 범위는 공개 조회다. 결제, 수강 등록, 강의 작성 화면과 쓰기 API, 역할별 권한은 포함하지 않는다.
- 기존 `/login` 화면과 인증 흐름은 유지한다.

## API

- `GET /courses`는 등록된 강의를 배열로 반환한다.
- `GET /courses/{course_id}`는 강의 한 건을 반환하고, 없으면 표준 404 응답을 반환한다.
- 성공/오류 응답은 기존 `{code, message, result}` 응답 형식을 따른다.
- 강의 데이터에는 목록용 제목, 강사명, 카테고리, 가격(KRW 정수), 대표 이미지 URL, 짧은 소개와 상세 페이지용 상세 소개 및 커리큘럼을 포함한다. 상세 응답은 목록 속성도 포함한다.
- 목록은 저장된 강의 순서를 일관되게 유지한다. 목록이 비어 있어도 성공 응답으로 빈 배열을 반환한다.

## 데이터와 화면

- 강의는 SQLite에 저장하고, 기존 앱의 모델 등록 및 스키마 생성 흐름에 연결한다.
- 목록 화면은 강의 카드에 대표 이미지, 제목, 강사, 분류, 가격, 짧은 소개를 보여준다. 강의 카드를 선택하면 해당 상세 화면으로 이동한다.
- 상세 화면은 제목, 강사, 분류, 가격, 상세 소개와 커리큘럼을 보여준다. 존재하지 않는 강의 ID는 사용자가 이해할 수 있는 미등록 상태로 표시하고 목록으로 돌아가는 동작을 제공한다.
- API 기본 주소는 `http://127.0.0.1:8000`이며 `VITE_API_BASE_URL`이 설정된 경우 이를 사용한다.
- 목록 로딩, 빈 목록, 요청 실패, 상세 404를 구분해 표시한다.

## 검증

- pytest로 SQLite 테스트 DB에서 목록/상세 조회, 응답 필드, 빈 목록, 미등록 ID를 검증한다.
- Jest로 강의 목록과 상세 화면의 API 응답 렌더링, 이동, 빈/오류 상태를 검증한다.
- 백엔드와 프런트엔드 전체 테스트를 실행한다. 개발 서버는 자동 실행하지 않는다.

## 구현 경계

- 백엔드와 프런트엔드는 각각 별도 git worktree 및 역할 에이전트에서 작업한다.
- 두 에이전트는 동일한 API 계약을 사용하며 독립된 폴더를 수정한다. 통합 후 전체 검증을 수행한다.
- 작업 시작 당시의 기존 미커밋 변경은 보존하고, 기능 변경과 충돌하는 경우 자동 덮어쓰지 않는다.
